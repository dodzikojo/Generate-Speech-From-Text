## Share with the project

@action: Use More, Share with project, and attach the maintained matrix to the Riverside training project.

Project sharing makes the matrix visible to project members and adds the project chip. It is appropriate when the rulebook belongs to one delivery team.

Manage clash sets controls which sets use the matrix for analysis. Project visibility and set assignment are related but not the same action.

## Publish to the Company library

@screen: On the prepared Business admin state, open Publish to company library and explain the consequences before confirming the demo copy.

The Company library is an organisation-wide template shelf. Publishing requires the applicable plan and an organisation admin. It detaches the matrix from any project because the library standard belongs to the organisation.

Members clone the published matrix into their own list. Clones are independent; later changes to the library original do not flow into existing copies.

Before publishing, remove project-specific classes, clear missing contacts, and name the standard so people choose the right one.

## Choose Add, Sync, or Regenerate deliberately

Add classes preserves the existing class list and rules, then creates pairings for newly discovered classes. Use it when a model introduces additional types but the older standard remains valid.

Synchronise replaces the matrix class list with the exact current extraction. Surviving rules keep their user edits while obsolete classes and their pairings leave the active matrix. Use it when the set should define the standard's current boundary.

Regenerate rebuilds the rule grid and is destructive to per-rule assignments. Use it only when the existing rulebook should be replaced, and review the warning before confirmation.

## Validate after maintenance

@action: Open the prepared updated set, compare its extracted classes with the matrix list, then download the detailed matrix workbook.

Check the new or removed classes, inspect several preserved rules, and run analysis against the updated set. Confirm that the expected contacts, priorities, statuses, and tolerances still appear as recommendations.

The Excel export should mirror the current cross-tab, including configured priority colours. Use it as a review artefact, not as an importable backup unless the deployed product explicitly provides an import path.

When sharing through the company library, publish a clean reusable standard. Project-specific contact names and classes can make an apparently helpful template unsafe for another job.
