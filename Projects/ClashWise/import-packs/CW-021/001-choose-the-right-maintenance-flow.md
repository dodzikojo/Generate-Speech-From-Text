## Preview old decisions surviving new classes

@visual: Show Fire Damper and Transfer Beam in the updated class list while the custom Ducts versus Beams rule remains High, Active, and assigned.

Model updates do not require the team to throw away a carefully maintained matrix.

For a model-profile matrix, rescan the connected Coordination setup first. Fingerprint-only drift records the new observation without changing its semantic revision. Changed mappings, selected classes, or raw search variants increment the revision and expose new coverage before installation.

Use Add missing classes from the setup when real scanned classes are absent from the matrix. Use the older Add classes flow when a published set is the source of truth. Use Sync when classes were added and removed, Regenerate only for an intentional fresh rule build, and Re-evaluate when the class structure is correct but priorities and statuses need new AI suggestions.

The preservation behaviour differs, so choose the flow before clicking through the familiar generation wizard or setup coverage action.

## Choose a profile standard or a dedicated set matrix

@screen: Compare Riverside Cycle 01 using Profile Default with a prepared set using Explicit assignment.

A profile-default set follows the federation standard. New sets receive the current default immediately; existing profile-default sets adopt a changed default on their next republish.

Create a matrix from a published clash set when that result package needs a dedicated rulebook or when no Coordination setup existed before detection. The extracted class mapping is stored on the set and the assignment becomes Explicit.

Explicit always wins over the profile default. Republish keeps that dedicated matrix and mapping until a user deliberately changes the assignment mode. This is why create-from-set remains valuable even though it is no longer the only matrix-creation order.
