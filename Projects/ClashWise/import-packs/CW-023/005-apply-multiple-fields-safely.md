## Select a bounded set

@action: Select the intended visible rows, read the selected count aloud, and open the bulk edit surface.

Never assume the current page equals the current selection. A saved filter, page change, or Select all matching action can include rows you do not see.

If the number differs from the prepared cohort, clear selection and rebuild it.

## Preview contact, status, tags, and due date

@screen: Choose Alex Structure, the prepared status, coordination tag, and date one week out, then pause at confirmation.

Review each selected field and whether empty values are being cleared or preserved. Bulk changes can affect contact, recommended status or priority, tags, due date, and other supported fields through the current action surface.

Apply only after the count and every field agree with the run sheet. Wait for the background mutation to complete before changing filters.

Use Close selected only when you intend to change lifecycle state. Do not create or select a workflow status named Closed. Open or Closed is an independent state, while configured statuses such as Active, Resolved, or Approved remain project-defined coordination labels.

## Separate discovery from mutation

Use filters, grouping, and sorting to discover a cohort. Then stop and describe that cohort in plain language before selecting it: for example, unresolved high-priority M E P clashes on Level zero two with no owner.

Compare the filtered count with the selected count. Select all visible rows only when the current action truly means the whole filtered cohort, not merely the first page.

Apply one logical change at a time when values have different owners. Setting responsibility, due date, and status in a single batch may be convenient, but it makes a mistaken scope harder to unwind and audit.

## Verify by reopening the cohort

@action: Clear the selection, reload the saved filter, and inspect three permanent clash numbers including the first and last visible row.

Confirm the new values persisted and the manual-change state is visible. Open one clash detail to check its history and matched-rule provenance.

Comments and titles deserve separate attention. A title should remain specific enough to distinguish similar geometry, and a comment should record a coordination fact or request rather than repeat what the status already says.

If a bulk operation partially fails, keep the completed count and failed numbers. Rebuild a retry cohort from the failures instead of applying the entire batch twice.
