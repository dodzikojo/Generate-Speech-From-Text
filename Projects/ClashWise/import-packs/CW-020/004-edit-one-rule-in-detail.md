## Set the Riverside sample rule

@action: In table view, search the target rule and edit priority High, status Active, contact Structural lead, tags coordination and opening, Detection Type Clearance, and tolerance 25 millimetres.

Open the Ducts versus Structural Beams rule. Set the values agreed for this synthetic project: High, Active, Structural lead, coordination and opening tags, Clearance detection, and twenty-five millimetres in the matrix's displayed length unit.

For an ordinary analysis-only matrix, tolerance documents the project's accepted clearance. When the matrix is linked to a Coordination setup, Detection Type and tolerance also define the managed Navisworks test on the next reconciliation. Saving the web rule does not run or update detection by itself.

Save the row and verify the chips and colour. A manual priority or status selection clears any old AI reasoning for that field because the project decision now owns the value.

## Use Active instead of deleting one rule

@screen: Toggle a prepared non-target rule inactive, show its retained data, then reactivate it.

Individual rules cannot be added or deleted directly. Generation and matrix-sync flows control the class-pair list.

Untick Active when one rule should be excluded from analysis without losing its configuration. A Coordination setup also omits that rule's managed test from its next package. Obsolete removal remains an explicit reconciliation choice. Reactivate the rule when it becomes relevant again.
