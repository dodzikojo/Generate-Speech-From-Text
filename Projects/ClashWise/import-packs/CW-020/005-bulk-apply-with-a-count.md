## Apply a safe value to a bounded region

@action: Filter the table to the prepared discipline or class cohort, choose Apply contact or use the cell popover, and read the affected rule count.

Bulk controls can apply priority, status, contact, or Detection Type across rules filtered by class or discipline. Define the cohort first and say the count aloud.

For this example, fill Structural lead only on rules without a contact. Keep Overwrite existing assignments off so intentional owners elsewhere in the cohort remain intact.

Apply and then use the NO CONTACT chip to verify the missing count falls by the expected amount.

## Contrast explicit and default states

@screen: Compare the edited target rule with a prepared rule that still has empty or generated defaults.

An explicit project value is visible on the rule and drives its future recommendations. An empty field cannot route that value. An AI-suggested starting value is still a matrix value, but it should be reviewed before the rulebook becomes a team standard.

Bulk convenience does not decide what is correct. The matrix owner remains responsible for the scope and chosen value.

## Test rule direction with a real clash

The cross-tab shows one mirrored class pairing, not two independent rules for A versus B and B versus A. Open a prepared clash and compare its two extracted classes with the row and column headings. Selecting the mirrored cell should reach the same rule.

That matters when a user assumes responsibility changes with element order. ClashWise matches the class pair; it does not create a second hidden rule because Navisworks happened to report the elements in the opposite order.

Use the matched-rule link on the clash to return to the exact matrix cell. This is the fastest way to prove which rule produced a recommendation.

## Establish defensible defaults

Set global priorities, statuses, contacts, tags, tolerances, and colours before filling hundreds of cells. Defaults cover ordinary pairings; explicit cell values capture genuine exceptions.

An inactive rule or missing contact should be deliberate and documented. Detection Type and tolerance are part of the rule's coordination meaning, not a way to hide a difficult clash after the fact. Profile-managed tests receive those definition changes only after a reviewed reconciliation, and the user still runs them in Navisworks.

After a bulk change, rerun analysis on a small set and inspect matched, unmatched, and intentionally overridden clashes. The matrix editor is only complete when the resulting recommendations can be traced and explained.
