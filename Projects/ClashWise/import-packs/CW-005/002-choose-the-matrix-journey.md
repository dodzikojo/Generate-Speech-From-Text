## Create a new matrix or attach an existing one

@action: Name the setup Riverside Coordination Setup and compare both matrix choices without leaving the first step.

The first choice is the rulebook journey.

Create a new matrix from the model inventory when this federation needs a fresh coordination strategy. The same class-based Wise generation pipeline used elsewhere in ClashWise will propose the rules after we select the model classes.

Use an existing accessible matrix when the team already trusts a personal, shared, manual, clash-set-created, or company-library matrix. Attaching it as the profile default does not grant permission to edit it. A read-only library matrix can still guide coverage, but it must be cloned before its classes are expanded.

For Riverside, choose Create a new matrix from the model inventory. Give the setup a durable federation name, not a weekly publish name. One setup is intended to survive many detection and publish cycles.

## Confirm every federated source

@action: Continue to Sources and read the architecture, structure, mechanical, electrical, and plumbing rows.

The Sources step identifies every model currently participating in the federation. ClashWise records a stable source identity, a readable file name, and an advisory fingerprint.

All five Riverside sources belong in this setup. You exclude unwanted classes later, not whole federation sources here. That full source list is what lets the binding detect an added, removed, renamed, or unmappable source before a future publish.

A changed file fingerprint is a normal model-drift signal. It does not automatically break the setup. A changed source roster is more significant and requires review before ClashWise binds the wrong rulebook.
