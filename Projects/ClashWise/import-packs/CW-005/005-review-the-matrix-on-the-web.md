## Open the profile-born matrix

@action: Choose Review matrix in browser and show Riverside Coordination Matrix with its origin and setup link.

The matrix page identifies this rulebook as originating from a model profile and links back to the Coordination setup. That provenance matters later when a clash set inherits the profile default.

Check that the expected class and discipline endpoints are present before refining individual rules. The matrix may contain pairings that never produce a clash. That is acceptable: the matrix defines the intended test space before detection, while materialisation will use only endpoints that exist in the scanned inventory.

Each active rule can become exactly one Navisworks clash test. A rule between different endpoints becomes an A-versus-B test. A rule whose endpoints are identical becomes a self-intersection test.

## Review detection intent before installation

@screen: Show Detection Type, Tolerance, Active, and the existing coordination defaults on several representative rules.

Choose Hard for direct intersections and Clearance when the rule requires a separation distance. Confirm the matrix length unit before entering tolerance; the plugin receives a canonical metres value after ClashWise converts from that unit.

Switch off a rule that should remain documented but should not create a test in this setup. Active rules with both endpoints present are the eligible test count.

Priority, workflow status, responsible contact, tags, and colours guide later analysis. Detection type and tolerance guide the native test definition. They are related parts of one rule, but Navisworks still owns detection and ClashWise still owns management and analysis.

Save the representative Riverside rules and leave the browser open for final inspection. Do not continue merely because generation completed; a generated rulebook becomes a coordination standard only after someone reviews it.

@visual: End on the active-rule count beside the open plugin window and the CW-006 title card.

Next, turn the reviewed matrix into managed search sets and clash tests, run them in Navisworks, and publish the first results.
