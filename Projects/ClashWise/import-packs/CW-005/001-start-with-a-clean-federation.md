## Preview the model-first outcome

@visual: Place the clean Riverside federated model beside its completed Coordination setup and reviewed matrix on the web.

This time, we are starting before clash detection. The Riverside federated Navisworks model has no search sets, no clash tests, and no clash results.

By the end of this lesson, the model will be connected to one Coordination setup and one reviewed Clash Matrix. The matrix will describe what should be tested before any results exist.

That reverses the earlier publish-first approach. It also matches the way many coordination teams work: decide the model classes, test pairings, detection type, and tolerance first; let Navisworks detect the results; then publish those results into ClashWise.

ClashWise still does not run clash detection. The plugin scans properties and creates definitions. Navisworks Clash Detective remains responsible for executing or updating every test.
