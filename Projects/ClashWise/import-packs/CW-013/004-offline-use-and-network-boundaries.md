## Prove local generation offline

@action: Use the documented offline test state, reopen Title Update, and generate the prepared one-off local test.

After the model download and an online sign-in, local Title Update can generate without an active internet connection. The model engine runs as a separate process so a generation failure should not bring down the Navisworks session.

An offline grace period still applies to entitlement verification. After an extended period without a check, the plugin asks you to reconnect once before continuing. Verify the current period in the installation article rather than baking it into the recording.

Do not test offline behaviour by interrupting a real download or a publish job. Use a prepared state after the model is fully installed.

## Distinguish inference from product records

@screen: Show local generation, then the account or title-audit surface as separate diagrams or screens.

During local inference, the clash inputs stay on the workstation. If cloud fallback is enabled and local generation fails, the retry sends the required clash element data to the ClashWise cloud; leave fallback off for a strictly local naming run.

When the computer reconnects, ClashWise can still verify the account and synchronise usage or title-change audit information used by the product. Publishing is another explicit network workflow and sends the selected clash set data to the web.

So local describes where naming is computed. It is not a claim that every ClashWise feature or every account record remains on this device.

## Plan storage and performance before the session

Model downloads are large enough to treat as a production dependency. Check the storage estimate shown in the model manager, keep comfortable free space beyond the download itself, and use a stable connection for the first installation. The first activation can also take longer while local files are prepared.

Hardware affects speed more than title quality alone. A smaller model that finishes a full test reliably is often a better production choice than a larger model that forces the operator to wait, overheat the laptop, or abandon the review.

Run the built-in test with the same kind of element names and properties used by the project. Record how long it takes, read the output, and only then commit the recording batch to that model.

## Prepare an offline recording check

@action: Disconnect the prepared network after the account and model are ready, generate one synthetic title, then reconnect.

Offline naming requires the model to be fully downloaded and active before the connection disappears. The plugin may still need online access for sign-in verification, cloud publishing, Wise, and account services.

For a real travel or site workflow, test offline behavior before leaving the office. A model listed in the manager is not enough; generate one title successfully while disconnected.
