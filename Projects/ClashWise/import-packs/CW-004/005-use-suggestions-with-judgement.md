## Let suggestions accelerate the first pass

@screen: Show Suggest with AI on one unmapped training source, review the proposed property pairs, then accept only after checking the samples.

The current Property Mapping window can suggest mappings from the properties and example values it finds in a source. Use Suggest with AI for the selected source, or Suggest all unmapped when the document contains several unfinished models.

Suggestions are a starting point, not verification. ClashWise shows the proposed pairs for review so you can accept or discard them. A property named Category may still contain the wrong kind of value, and a source identifier that works on one export may be empty on another.

After accepting a suggestion, run Sample Elements exactly as you would after a manual mapping. If a column is consistently wrong, replace that field and sample again. The useful time saving is finding likely properties faster; the coordinator still confirms that the returned values support the workflow.

## Know when to review the mapping again

@visual: Show a newly appended source with a warning icon, then a language or export variant with different property names.

Mappings persist, but the model environment can change. Review them when a new source is appended, a consultant changes export settings, a property is renamed, or the Navisworks display language changes.

Use the warning icons and preview grid as evidence. Do not rebuild every mapping simply because a model was updated, and do not assume an old mapping remains correct after its underlying property structure changed.

The safest habit is small and repeatable: sample one or two elements from every source type before an important publish, then correct only what the preview proves is wrong.
