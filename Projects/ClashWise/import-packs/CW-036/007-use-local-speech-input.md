## Dictate, inspect, then send

@action: Select the microphone and say: Focus clash number twenty-seven.

The microphone transcribes speech locally into the composer. On the first use, the local speech model may need to prepare or download. The interface distinguishes preparing, listening, and transcribing.

Pause after the sentence and let the text settle. Read the transcription before sending, especially the clash number, level, and discipline names. Speech input saves typing; it does not remove the need to review the request.

If the microphone is unavailable, the model cannot start, or no speech is detected, keep working by typing. A speech failure does not need to block the coordination workflow.

## Phrase requests for verification

Put the object first, then the action and exact value: On Riverside Week thirty-eight, set clash number twelve's contact to Morgan M E P. That structure reduces ambiguity and makes the completion row easy to compare with the request.

Use one message to batch closely related safe changes when the returned cohort is already visible. Use separate messages for unrelated changes or where each outcome needs its own approval and audit explanation.

For model operations, state whether you want select, focus, or isolate. For data operations, state whether you want Wise to find clashes, update fields, add a comment, create a set, or begin the matrix flow.

## Recover from an unsafe or unclear answer

If the returned cards do not match the question, do not continue with these or all of them. Clear the scope, refresh the set, or restate the cohort using permanent clash numbers.

If a tool row fails, read its reason. Missing permission, stale data, unavailable matrix, or an object outside the current model requires a different correction. Sending the identical instruction repeatedly can consume actions without improving the state.

After every mutation, check the completion row, refresh the card, inspect the native model or web record, and use history when the change must be audited. Wise accelerates the workflow; those verification steps keep the operator in control.
