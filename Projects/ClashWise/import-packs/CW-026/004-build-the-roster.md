## Add internal and external attendees

@action: Add two synthetic members and one external contact using the attendee search and cards.

Add attendees by name or email. Matrix contacts can appear as suggestions, and each card lets you verify name, company, and email.

At the scheduled stage, the roster records who is expected. Guest invitation links become meaningful when the session is Active and rooms are enabled.

Use only the prepared example identities. Do not send a rehearsal invitation to a real address.

## Understand attendee states

@screen: Show not joined on the scheduled roster and prepared invited and joined-live examples from another synthetic session.

Not joined means listed but not observed in the room. Invited appears only when an invitation email was actually sent. Joined live means the person entered the live viewer.

These states later appear in minutes and the PDF, so do not mark attendance manually before the meeting begins.

## Configure defaults as policy, not convenience

Organisation Admins can decide whether session edits automatically mark clashes reviewed and whether a default due date is applied. The due-day value should match the team's normal response window.

These are starting behaviors. They do not decide the engineering outcome of a clash and they do not create a meeting record before a session is active.

Review the current close-status and room settings shown by the deployed product. Keep fast-changing or plan-dependent details in the linked help article.

## Run the session preflight

@action: Open the scheduled Riverside session from the clash set Coordination panel and work through the prepared checklist.

Confirm the set and matrix are current, analysis has completed, the intended clashes are present, and the attendee list uses synthetic addresses for training. Check the session date and time zone, then inspect any invitation states.

Open one target clash and confirm its permanent number, viewpoint, responsibility, and due-date state. Make sure the browser profile has permission to edit the set and that the second participant can reach the room.

Only then select Start. A scheduled session is a plan; the Active state is what begins automatic recording of supported coordination changes.
