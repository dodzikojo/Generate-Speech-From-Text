## Start with the job, not the menu

@screen: Place Navisworks and the ClashWise web dashboard side by side.

ClashWise has two connected workspaces, but you do not need to memorise every control.

Use one simple rule. Work that depends on the open Navisworks document begins in the plugin. Shared review, coordination, reporting, and organisation management happen on the web.

So the everyday loop is: prepare the model and coordination strategy, run detection in Navisworks, publish the results, coordinate on the web, then sync supported agreed values back.

Before working, check two pieces of context. In Navisworks, confirm the intended federated model is open. On the web, confirm the organisation switcher shows the intended organisation. Those two checks prevent most wrong-document and wrong-workspace mistakes.

## The plugin prepares and connects the model

@action: Sweep across the ClashWiseAI ribbon from left to right without opening every dialog.

The General panel contains the tools that prepare Navisworks data.

Title Update generates clearer clash names. Local AI installs and manages the models that can run naming on this computer. Property Mapping tells ClashWise where element names, identifiers, categories, levels, types, and source files are stored. Group Clashes organises results into useful packages. Sets and Clashes can build definitions manually or start Create from ClashWise matrix for a model-first Coordination setup.

The exact buttons depend on the installed edition. Full Suite exposes the complete workflow; the smaller Starter edition focuses on clash naming.

Each tool has a narrow job. Property Mapping prepares element data used by naming, publishing, filters, and reports. The Coordination setup scanner separately captures the class, optional discipline, and exact source values needed to build matrix-driven searches. Title Update changes the text attached to existing results; it does not create new results. Group Clashes and Sets and Clashes structure work inside the open document so detection and the published set are easier to manage.

This separation is useful when troubleshooting. If a published clash is missing a level or element category, return to Property Mapping and the model data. If the team disagrees with a recommended owner or priority, return to the matrix and analysis workflow on the web.
