## The Clash Management panel

@screen: Highlight Chat, Publish, Update, and Sync on the ribbon.

The Clash Management panel connects the open Navisworks document to the shared web workspace.

Chat opens Wise, the ClashWise assistant, with context from the model or a published clash set. Publish creates a new web clash set from selected existing Clash Detective tests. Update refreshes an existing set after the model or test results change. Sync writes supported agreed values and web-created groups back to matching Navisworks clashes.

Remember the product boundary: Navisworks detects the clashes. These controls do not run clash detection.

Dashboard opens the web app. Help opens the searchable help centre. Report Bug creates a support report and can include useful diagnostic attachments. The Visibility panel gives you quick view, hide, show-all, and reset controls while you investigate the model.

## The web app turns results into a worklist

@action: Open Clash sets from the web drawer and point to the selected set, grid, matrix selector, and main actions.

Clash sets is the main coordination surface. Select a published set in the left pane, then use the grid to search, filter, group, sort, edit, and bulk-manage clashes.

The set header connects the larger workflow. Confirm the inherited or explicit Clash Matrix, run or inspect analysis, open Insights, review in three dimensions, or open Coordination sessions. A profile-bound first publish may already have its matrix assigned and analysis queued after property upload completes.

Every clash has a permanent number within its set. That number appears in the grid, detail dialog, viewer, sessions, reports, and links. Use clash number first when you discuss or share an issue.

The source columns and the coordination columns tell different parts of the story. Published test, group, viewpoint, and original values explain what came from Navisworks. The matrix, matched rule, recommendations, responsibility, tags, due dates, comments, and session history explain how the team is managing it.

This is why Publish, Update, and Sync are separate commands. Publish starts a new shared record. Update carries later model results into that same record. Sync travels in the other direction and writes selected agreed values onto matching clashes in the open Navisworks document.
