## Run or update the tests in Clash Detective

@action: Open Clash Detective, select the new ClashWise-prefixed Riverside tests, and run them manually.

This is the handoff between the products. Navisworks executes the tests and produces the clash results. ClashWise does not press Run, schedule native detection, or claim those results as its own detector.

Review the counts before publishing. A zero-result test may be correct. An unexpectedly huge result often means the search predicates or tolerance need attention. Correct the source mapping or matrix rule, refresh the materialisation preview, and reconcile again rather than manually editing every generated test.

Use the prepared Riverside results for the recording and save the NWF. The stable rule identifiers remain in the local manifest, so later matrix changes can be compared with what was installed.

## Verify publish property mapping

@action: Open Property Mapping and preview representative elements from every source before publishing.

The setup mapping controls class and discipline predicates. The full publish mapping still supplies the readable name, source identifier, category, level or layer, type, and source values used across ClashWise.

Preview more than one element from each source type. The class and source choices used for the setup should agree with the values later published for analysis. If a consultant changed its export properties, repair and sample the mapping before uploading results.
