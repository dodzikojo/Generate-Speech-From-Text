## Review the project tag library

@action: Open the Tags tab and locate the Weekly, M E P, and Structure tags aggregated from the two sets.

The Tags tab gathers every distinct tag used across the project's clash sets. Counts show how widely each label is used.

This makes inconsistency visible. If one set says M E P and another says Mechanical, agree the standard before adding more data.

Project Owners can rename a tag across the project or delete it from every affected clash. Those are broad changes. Read the confirmation, check the number of clashes, and remember the audit log records the per-clash changes. Members can use the library but cannot perform that maintenance.

## Make useful views reusable

Saved filters created in a project are available to its members. Build them around recurring review questions, such as unresolved structure-versus-mechanical clashes, rather than one meeting's temporary curiosity.

The value is consistency: a teammate can open the same defined cohort without recreating each facet and condition. Keep ad hoc exploration as an unsaved filter when it is unlikely to be useful again.
