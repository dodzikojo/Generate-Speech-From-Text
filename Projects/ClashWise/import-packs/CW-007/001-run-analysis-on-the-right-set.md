## Preview a traceable recommendation

@visual: Open a fully analysed Riverside row, showing clash number, matched rule, recommended priority, status, and responsible contact.

Analysis turns a published clash list into a rule-driven worklist. Here, clash number twelve carries recommendations and a link back to the exact matrix rule that produced them.

The trace matters as much as the answer. A coordinator can see the source clash information, the current saved coordination values, and the matrix recommendation as separate things.

ClashWise does not hide a fixed discipline rulebook behind this process. The classes, rules, defaults, tolerances, tags, and contacts come from the assigned Riverside matrix. Classification can use captured properties and AI assistance, but the project rulebook remains visible and editable.

## Confirm the matrix and analysis state

@action: On Riverside Cycle 01, confirm Riverside Coordination Matrix and show the analysis queued by publish finalisation.

Always confirm the set and matrix before interpreting results. A profile-bound publish queues analysis automatically after every current clash has its property document. If the set says Awaiting properties, publishing succeeded but analysis is intentionally held until finalisation is complete.

Progress appears both on the set and in the clash-set list. The work continues in the background, so you can navigate elsewhere instead of waiting on this page. A filtered view inherits its parent's results and cannot run analysis independently; use the parent clash set.

Run analysis remains available when you deliberately need a rerun against the current matrix. During a long run, the action becomes Stop analysis. Use it when the wrong matrix or set was selected, not as a way to make an estimated completion time more predictable.
